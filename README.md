# MOLODIST · Beauty Plan CRM

CRM під бюті-плани, звʼязана з CleverBox. Основа — картка пацієнта з бюті-планом (процедури, кількість, ціни, домашній догляд) і автоматичне відстеження реалізації за даними CleverBox.

## Що вміє

| Блок | Як працює |
|---|---|
| **Бюті-план** | PDF з Observ 520x (завантаження у веб або в ТГ-чат) → парситься пацієнт, лікар, дата, процедури (к-сть × ціна), засоби (обʼєм, ранок/вечір, посилання на molodist.store), разом. Повторне завантаження того ж плану оновлює його. |
| **CleverBox → CRM** | Кожні 2 год (8:05–20:05): привʼязка пацієнтів (телефон → ПІБ), надані послуги (`/services/sales`), продані засоби (`/products/sales`), майбутні записи (`/clients/visits`), довідники послуг і лікарів. |
| **Реалізація плану** | Для кожної позиції: виконано / записано / залишок, сума реалізації, % плану, чи записана людина і на коли, яка наступна процедура. |
| **KPI** | По плану, по кожному лікарю і по всіх: сума планів, реалізовано, %, записано наперед, % активних із записом, конверсія в старт, середній план, прострочені. Фільтр за періодом. |
| **Фінпрогноз** | 6 місяців: підтверджено записами + очікується за інтервалами плану + повторний догляд (за тривалістю засобів). |
| **ТГ-бот** | Приймає PDF планів і фото з робочих чатів; фото з підписом «Прізвище Ім'я» → у картку. Щодня (пн–сб, 10:00) дайджест адмінам: «не записані» і «закінчується догляд». Медичні нотатки в ТГ не потрапляють. |
| **Google Sheets** | Аркуші «Плани», «Позиції», «KPI лікарів», «Прогноз» — оновлюються після кожного синку або кнопкою. |
| **Кабінети й ролі** | Власник (усе), Адміністратор (пацієнти, плани, нагадування, без фінансів і мед. нотаток), Лікар (лише свої пацієнти та свій KPI). Журнал дій: хто що змінив. |
| **REST API** | `/api/v1/*` за API-ключами з дозволами read / write / medical. Вебхуки CRM → n8n з підписом HMAC. |

## Розділи (бокове меню)

Логіка кожного розділу побудована навколо бюті-плану, дані — з CleverBox (синк кожні 2 год).

| Розділ | Що показує | Хто бачить |
|---|---|---|
| **Клієнти** | База з сегментами: з бюті-планом, потребують уваги, без плану (потенціал для консультації), сплячі > 90 днів, нові, ДН найближчі 14 днів, VIP (топ-10% за виручкою). LTV, візити, наступний запис, статус плану. | усі (лікар — свої) |
| **Календар** | Тиждень/день: записи CleverBox (пацієнти з планом виділені), «очікується за планом — без запису», дедлайни задач. Фільтр за спеціалістом. | усі (лікар — свої) |
| **Запис з плану** | Кнопка «Записати» біля процедури в картці: вільні слоти CleverBox на дату → спеціаліст (лікар плану першим) → запис створюється в CleverBox, у CRM і закриває задачу «записати». | власник, адмін |
| **Задачі** | Автозадачі: «записати на процедуру», «повторний догляд», «дозамовити товар» — без дублів, закриваються самі, коли пацієнт записався/купив. Ручні задачі з виконавцем, терміном, пріоритетом, результатом; сповіщення в Telegram. | власник — усі; адмін — свої і черга адмінів; лікар — по своїх пацієнтах |
| **Продукти** | Засоби: призначено в планах → куплено (конверсія), виручка, потреба, залишок, тривалість засобу, мін. залишок, посилання на molodist.store. Процедури: призначено/виконано/записано, суми. | власник, адмін |
| **Склад** | Залишки CleverBox проти попиту з планів: не куплене з планів + повторні покупки на 30 днів + мін. залишок → «дозамовити N шт». | власник, адмін |
| **Фінанси** | Виручка з чеків (послуги/товари, знижки, способи оплати, по спеціалістах), частка пацієнтів з бюті-планом, факт за 12 міс. + прогноз за планами. | власник |

## Скрипти і розсилки

| | Як працює |
|---|---|
| **Скрипти в задачах** | У задачах «Записати на процедуру», «Повторний догляд» і в картці пацієнтки — готовий скрипт дзвінка і текст повідомлення з її планом: імʼя, лікар, скільки процедур пройдено, наступна процедура, чому важливо не пропускати інтервал (довідник процедур), що дасть курс, засіб і посилання на molodist.store. Копіювати одним кліком або надіслати (Telegram-бот → Viber → SMS). Медичні нотатки в скрипти не потрапляють. Шаблони і довідник процедур редагує власник у «Скрипти». |
| **Розсилки** | Аудиторія з сегментів «Клієнтів» (сплячі, без плану, ДН, VIP, потребують уваги…) + фільтри (лікар, джерело, виручка). Канали за пріоритетом: бот пацієнтів у Telegram (безкоштовно) → Viber з резервом SMS (TurboSMS). Превʼю: скільки отримають, яким каналом, хто відсіяний і чому, вартість; тест собі; запуск зараз або за розкладом. Захист: відписані не отримують, ліміт 1 розсилка / 14 днів на клієнта, тихі години 20:00–09:00, захист від дублів. Результат: доставлено, записались/прийшли за 14 днів, виручка, відписки. Готують власник і адміни, запускає — власник. |
| **Бот пацієнтів** | Ваш бот на OpenClaw підключається через API з ключем «bot»: привʼязка за телефоном, відписки, «мій бюті-план». Специфікація — `docs/openclaw-patient-bot.md`. |

## Дані: експорт, імпорт, перенос (розділ «Дані»)

| Що | Як |
|---|---|
| **Звіти** | Excel (.xlsx) або CSV за період: плани, позиції з реалізацією, KPI лікарів, фінпрогноз. Кожна роль отримує лише те, що бачить (адмін — без KPI і прогнозу, лікар — свої пацієнти). |
| **Файли** | ZIP з усіма фото й PDF по папках пацієнтів; у картці — «Файли ZIP» і «Друк / PDF» (друкована картка з планом). |
| **Імпорт таблиць** | Excel/CSV з будь-якої системи, колонки розпізнаються автоматично (укр./англ./рос. заголовки, кодування UTF-8 і Windows-1251). Типи: пацієнти, бюті-плани (построчно), історія візитів і покупок. Аркуші «Пацієнти», «Плани», «Історія» — кожен своїм типом. Повторний імпорт не дублює. Є шаблон Excel. |
| **Пакет PDF** | ZIP з PDF Observ → усі плани за раз. |
| **Перенос з CleverBox** | Фонова задача з прогресом: послуги, лікарі, клієнти (з телефонами), надані послуги й продажі товарів за 6–60 міс., майбутні записи. |
| **Перенос з іншої CRM** | Через Excel: пацієнти → історія → плани. |
| **Резервна копія / переїзд** | Повна копія (база + файли) одним ZIP; відновлення на новому сервері повністю замінює дані. Лише власник, з підтвердженням. |

API: `GET /api/v1/export/report.xlsx`, `POST /api/v1/import` (файл + `kind`).

## Кабінети

При першому запуску створюється власник: логін `OWNER_LOGIN` (за замовчуванням `vadim`), пароль `ADMIN_PASSWORD` з `.env`. **Після входу змініть пароль у «Мій кабінет».** Інших користувачів створює власник у «Доступи й API → Користувачі». Для ролі «Лікар» обовʼязково привʼяжіть його до лікаря з бюті-планів.

## REST API

Ключ: «Доступи й API → API-ключі» (показується один раз). Swagger-документація — `/api/docs` (для власника після входу).

| Метод | Що робить | Дозвіл |
|---|---|---|
| `GET /api/v1/patients?q=&flag=red&doctor_id=` | пацієнти зі статусом останнього плану | read |
| `GET /api/v1/patients/{id}` | пацієнт: плани, візити, покупки | read |
| `POST /api/v1/patients` · `PATCH /api/v1/patients/{id}` | створити/оновити (пошук за cleverbox_id → телефоном → ПІБ) | write |
| `GET /api/v1/plans?status=&date_from=&date_to=` · `GET /api/v1/plans/{id}` | плани з реалізацією по позиціях | read |
| `POST /api/v1/plans` | створити план з JSON (з іншої системи / форми) | write |
| `POST /api/v1/plans/upload` | PDF Observ | write |
| `PATCH /api/v1/plans/{id}` | статус, к-сть, ручні відмітки, інтервали | write |
| `GET /api/v1/kpi` · `GET /api/v1/forecast` · `GET /api/v1/reminders` · `GET /api/v1/doctors` | аналітика | read |
| `POST /api/v1/sync` | синк з CleverBox зараз | write |

Медичні нотатки віддаються лише ключам з дозволом `medical`.

**Вебхуки** (CRM сама шле POST): `plan.created`, `plan.updated`, `reminders.daily`, `sync.done`. Тіло `{"event","sent_at","data"}`, підпис у заголовку `X-CRM-Signature` = HMAC-SHA256(секрет, тіло).

## Логіка (налаштовується)

- **Процедура зарахована**, якщо в CleverBox є надана послуга після дати плану, назва якої збігається на ≥60% слів — або вручну зіставлена на сторінці «Зіставлення з CleverBox». Резерв — поле «Ручна відмітка» в картці.
- **Інтервали між процедурами** за замовчуванням: IPL 28 дн, гігієна 30, пілінг 14, біоревіталізація/полінуклеотиди 14, ботулінотерапія 120… Редагуються в картці.
- **Тривалість засобу** = обʼєм ÷ (витрата за нанесення × разів на день). Напр. очищувальний гель 245 мл ранок+вечір ≈ 61 день. Редагується в картці.
- **«Не записана»** — немає майбутнього запису, а наступна процедура вже «на часі» (через 2 дні після консультації для першої, далі — за інтервалом). Повтор нагадування — раз на тиждень.
- **«Догляд закінчується»** — за 10 днів до розрахункового кінця засобу (один раз на кожну покупку).

## Запуск на VPS

**Перед стартом:** DNS A-запис домену (напр. `crm.molodist.com.ua`) → IP сервера; відкриті порти 80 і 443.
Якщо на сервері вже є nginx/Caddy на 80/443 (напр. для інших сервісів) — приберіть сервіс `caddy` з `docker-compose.yml`
і проксуйте домен на контейнер `app:8000` наявним проксі.

```bash
cd /opt && unzip molodist-crm.zip && cd molodist-crm
cp .env.example .env && nano .env      # DOMAIN, PUBLIC_URL, паролі, токени, BACKUP_PASSWORD
openssl rand -hex 32                   # → SECRET_KEY
docker compose up -d --build           # Postgres + CRM + Caddy (HTTPS-сертифікат отримується сам)
docker compose logs -f app caddy
```

Після входу: «Мій кабінет» → змініть пароль і вкажіть свій Telegram chat ID (сюди йдуть сповіщення про збої і зашифровані бекапи; спершу напишіть боту `/start`, потім `/id`).

### Безпека й надійність (вбудовано)
- **HTTPS** — Caddy з автосертифікатом Let's Encrypt, HSTS і захисні заголовки; ліміт завантаження 2 ГБ; CRM назовні напряму не доступна.
- **Захист входу** — 5 невдалих спроб на логін за 15 хв → блок на 15 хв (на IP — поріг 20, щоб помилка колеги не блокувала всю клініку); перебір API-ключів → 429. Усе в журналі, власнику — сповіщення.
- **Автобекапи** — щодня о `BACKUP_HOUR`:30 база + фото/PDF у `BACKUP_HOST_DIR` (краще окремий диск), `BACKUP_KEEP` останніх; друга копія в `BACKUP_COPY_DIR` (другий диск або змонтована хмара); зашифрована (`BACKUP_PASSWORD`) копія — власнику в Telegram (≤ 50 МБ, інакше лише база). **Пароль бекапів збережіть окремо** — без нього копію з Telegram не відновити.
- **Сповіщення про збої в Telegram** — синк CleverBox (з підказкою, що робити: токен/IP/недоступність), окремі модулі, бекап, нагадування, фонові задачі; без спаму (повтор раз на 6 год) і з повідомленням «✅ відновлено».
- **Швидкодія** — статуси планів рахуються пакетно (≈7 запитів до БД незалежно від кількості планів) і запамʼятовуються в межах запиту. Заміри на 5 000 клієнтів / 400 планів / 25 000 візитів: дашборд ~0,15 с, клієнти ~0,35 с, решта розділів 0,1–0,4 с.
- **Один процес** — планувальник і бот усередині застосунку; не запускайте кілька копій `app`.

Тести (покладіть будь-який PDF плану Observ у `tests/sample_plan.pdf`): `docker compose exec app pytest -q`

### Підключення
1. **CleverBox**: Налаштування → REST API → згенерувати токен → `CLEVERBOX_TOKEN`. **Додайте IP VPS у дозволені адреси.** На дашборді натисніть «Синхронізувати» — перший синк тягне 120 днів історії.
2. **Telegram**: створіть бота в @BotFather → `TELEGRAM_BOT_TOKEN`. Додайте бота в робочі чати і чат адмінів, у кожному напишіть `/id` і впишіть ID у `.env`. Перезапустіть `docker compose restart app`.
3. **Google Sheets** (за бажанням): service account у Google Cloud → JSON-ключ у `data/google-sa.json`, розшарте таблицю на email акаунта, ID таблиці → `GOOGLE_SHEET_ID`.

### Команди бота
`/plan Прізвище` — статус плану · `/digest` — нагадування зараз · `/to Прізвище Ім'я` (відповіддю на фото) — привʼязати фото · `/id` — ID чату.
