# Бот турботи @molodist_assistant_bot (OpenClaw) ↔ MOLODIST CRM

CRM і бот працюють у парі:
- **бот → CRM**: повідомляє, хто з пацієнтів у боті (привʼязка за телефоном), відписки, і може показати пацієнту «мій бюті-план»;
- **CRM → пацієнт**: розсилки й повідомлення з задач адміни шлють **токеном цього ж бота** (`PATIENT_BOT_TOKEN` у `.env` CRM).
  Надсилання через Bot API не заважає OpenClaw отримувати оновлення (polling/webhook лишаються як є).

## 1. Ключ
CRM → «Доступи й API» → API-ключі → дозвіл **bot** (лише він). Ключ передається в заголовку `X-API-Key`.
Такий ключ не може читати базу пацієнтів — лише методи нижче.

## 2. Методи (база `https://<домен CRM>/api/v1`)

### Привʼязка: після «Поділитися контактом» у боті
```
POST /bot/link
{"chat_id": "123456789", "phone": "+380671112233", "username": "olena_d",
 "name": "Олена", "create_if_missing": false}
→ {"linked": true, "created": false, "patient_id": 42, "name": "Олена Даниленко"}
→ {"linked": false, "reason": "пацієнта з таким телефоном немає в CRM"}
```
`create_if_missing: true` + `name` — створити нову картку (джерело «Telegram-бот»), якщо номера немає в базі.

### Відписка / підписка на розсилки (кнопка «Не надсилати пропозиції»)
```
POST /bot/unsubscribe   {"chat_id": "123456789"}
POST /bot/subscribe     {"chat_id": "123456789"}
```
Сервісні повідомлення (нагадування про запис з задач) відписка не блокує — лише маркетингові розсилки.

### Пацієнт вийшов з бота / заблокував
```
POST /bot/unlink        {"chat_id": "123456789"}
```
(CRM і сама відвʼязує, якщо Telegram відповів «bot was blocked».)

### «Мій бюті-план» — для кнопки в боті
```
GET /bot/patient/123456789
→ {"name": "Олена", "subscribed": true, "next_visit": "2026-10-22T11:00",
   "plan": {"title": "Beauty Plan Anti Age", "date": "2026-10-10", "doctor": "Дарʼя Колган",
            "procedures": [{"name": "IPL-терапія обличчя", "done": 1, "total": 4, "booked": 1}],
            "progress_pct": 40, "next_procedure": "IPL-терапія обличчя", "next_due": "2026-11-07",
            "home_care": [{"name": "…Azelorosa…", "url": "https://molodist.store/…", "usage": ["evening"],
                           "bought": true, "ends_about": "2026-12-20"}],
            "routine_comment": "Патчі під очі Rejuran"}}
```
Медичних нотаток і цін тут немає.

## 3. Відповіді пацієнтів
Відповіді на розсилки приходять у бот (OpenClaw) — їх обробляє бот/адміни як зазвичай.
Записи після розсилки CRM рахує сама (з CleverBox) у вікні атрибуції.

# Версія 2 (16.11.2026): кабінет пацієнта, аналізи, повідомлення, нагадування з кнопками

**Головне правило:** усе нове вмикає власник у CRM («Налаштування → Бот турботи»). Бот перед показом меню бере
`GET /bot/config` і показує лише ввімкнені пункти. Поки функцію вимкнено — пункту в меню немає.
Повідомлення пацієнтам від CRM додатково блокує загальна пауза («Налаштування → Канали»).

### Ролі
- Бот (OpenClaw) — інтерфейс для пацієнта: меню, кнопки, тексти, отримання оновлень Telegram (як зараз).
- CRM — джерело даних. Дані пацієнта бот бере лише з CRM і лише для **свого** chat_id. Нічого не зберігає в себе понад потрібне для діалогу.

### Конфіг
```
GET /bot/config
→ {"features": {"cabinet": false, "files": false, "messages": false, "certs": false, "reminders": false, "login": false},
   "callback_format": "mcrm:<confirm|reschedule|cancel>:<appointment_id>", "actions": {...}}
```
Кешувати не довше 5 хвилин.

### Меню «Мій кабінет» (features.cabinet)
| Кнопка | Метод |
|---|---|
| Мої записи | `GET /bot/patient/{chat_id}/records` → `upcoming[]` (id, when, service, doctor, status_text, actions) і `past[]` |
| Мій баланс, абонементи, сертифікати, знижки | `GET /bot/patient/{chat_id}/wallet` → `balance` (гроші на рахунку, **не бонуси**), `subscriptions[]` (visits_left / money_left, valid_to), `certificates[]` (balance, valid_to), `discount_pct`, `bonuses` |
| Мій бюті-план | `GET /bot/patient/{chat_id}` (як і раніше: процедури done/total, прогрес %, наступна процедура, домашній догляд) |

Під майбутнім записом — ті самі кнопки, що в нагадуванні (`actions`): «Підтвердити», «Перенести», «Скасувати».

### Мої аналізи (features.files)
```
GET  /bot/patient/{chat_id}/files              → {"files": [{"id", "name", "date", "type"}]}
GET  /bot/patient/{chat_id}/files/{id}         → сам файл (надіслати пацієнту документом)
POST /bot/patient/{chat_id}/files?caption=...  multipart, поле file (PDF / фото, до 20 МБ)
→ {"ok": true, "duplicate": false, "file_id": 123}
```
Пацієнт надсилає документ або фото в розділі «Мої аналізи» → бот завантажує файл у CRM. Файл потрапляє в картку (категорія
«Аналізи»), адміністратору — задача. Той самий файл удруге не додається (`duplicate: true` — відповісти «Цей файл уже є в картці»).
Сам вміст аналізів бот не читає й не переказує.

### Написати адміністратору / головному лікарю (features.messages)
```
POST /bot/patient/{chat_id}/message  {"to": "admin" | "chief", "text": "..."}
→ {"ok": true, "task_id": 55}
```
CRM створює задачу й шле сповіщення адресатам (без тексту повідомлення). Пацієнту: «Передали адміністратору / головному лікарю,
відповімо найближчим часом». Відповідь адміністратор дає в картці (повідомлення пацієнту йде через цей же бот).

### Купити сертифікат або абонемент (features.certs)
```
GET  /bot/offers  → {"certs": [{id, name, price, nominal, days}], "subs": [{id, name, price, visits, per, save, pct, days}], "rules": {...}}
POST /bot/patient/{chat_id}/order  {"kind": "cert", "id": 2, "to": "Олена", "to_phone": "+380671112233"}
                                   {"kind": "sub", "id": 7}
→ {"ok": true, "title": "...", "price": 2000, "pay_url": "https://pay.monobank.ua/..."}
```
Для сертифіката імʼя й телефон отримувача обовʼязкові: спитати в пацієнта двома кроками. Покажіть правила з `rules.cert_rules`.
Для абонемента покажіть вигоду: «{per} ₴ за процедуру, вигода {save} ₴ (−{pct}%)».
Після оплати CRM сама проводить продаж: сертифікат — на номер отримувача, абонемент — на пацієнта. Бот нічого не підтверджує.
Якщо `pay_url` немає — «Адміністратор звʼяжеться з вами для оплати».

### Нагадування з кнопками (features.reminders)
CRM сама шле нагадування напередодні візиту **токеном цього бота** з inline-кнопками:
`callback_data = "mcrm:confirm:<id>" | "mcrm:reschedule:<id>" | "mcrm:cancel:<id>"`.
Бот має обробити ці callback_query (вони приходять у бот, не в CRM):

1. **confirm** → `POST /bot/appointment/{id}/answer {"chat_id": "...", "action": "confirm"}` → показати `reply`,
   прибрати кнопки з повідомлення (editMessageReplyMarkup).
2. **cancel** → спитати «Підкажіть, будь ласка, чому скасовуєте?» (кнопки: «Захворів(ла)», «Змінились плани», «Інше» + вільний текст)
   → `POST ... {"action": "cancel", "reason": "..."}` → `reply`.
3. **reschedule** → спитати «На коли вам зручно?» (вільний текст) → `POST ... {"action": "reschedule", "wish": "..."}` → `reply`.
   Запис лишається, адміністратор переносить сам і звʼязується з пацієнтом.

Відповідь CRM: `{"ok": true, "status": "confirmed", "reply": "текст для пацієнта"}`. Якщо `ok: false` — показати `reply`
(запис уже не активний). Завжди `answerCallbackQuery`, щоб кнопка не «крутилась».

У CRM: візит стає «Підтверджено» / «Скасовано» з позначкою «через Бот турботи», адміністратори отримують сповіщення,
на перенесення — задача з бажаним часом.

### Правила
- Ключ лише зі scope **bot**, зберігати в секретах агента, у логи не писати. Ліміт — до 2 запитів/с.
- Дані пацієнта — лише власнику chat_id. Ніяких медичних подробиць у текстах бота, лише те, що віддає CRM.
- Не використовувати російські сервіси. Не надсилати розсилки від себе — розсилки робить CRM.
- Помилки API: 404 — пацієнта не привʼязано (запропонувати «Поділитися контактом»), 400 — показати `detail` пацієнту
  простими словами; 5xx — «Сервіс тимчасово недоступний, спробуйте пізніше» і до 3 повторів.
- Перевірка: «Налаштування → Бот турботи» — лічильник підписаних, останні дії бота; картка пацієнта — позначка «Telegram-бот ✓»,
  задачі, аналізи в «Аналізи», історія візиту.
