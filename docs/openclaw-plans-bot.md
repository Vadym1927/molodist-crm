# Інструкція агенту OpenClaw: бюті-плани з бота консультацій → CRM

## Роль і межі
Ти — агент автоматизації MOLODIST на VPS. Лікар надсилає PDF бюті-плану (апарат OBSERV 520x) у **бот консультацій**.
Завдання: кожен такий PDF автоматично передавати в CRM, щоб план зʼявився в картці пацієнта.
Сам бот консультацій працює як раніше (пацієнт отримує план так само). Код CRM, Nginx, `.env` CRM, Instagram/Direct — не чіпати.

## Ключ API
- Власник створює в CRM ключ API зі scope **write** (Доступ → API: https://crm.molodist.com.ua/access/api) і сам кладе його у твій конфіг / змінну оточення,
  напр. `MOLODIST_CRM_KEY`. У чат, логи, звіти й код ключ **не писати**.
- База: `https://crm.molodist.com.ua/api/v1`

## Що зробити
1. У обробнику бота консультацій: коли приходить документ `*.pdf` (від лікаря / адміністратора — не від пацієнта),
   після звичайної обробки ботом — завантаж файл і відправ у CRM:
   ```bash
   curl -sS -X POST "https://crm.molodist.com.ua/api/v1/plans/upload" \
        -H "X-API-Key: $MOLODIST_CRM_KEY" \
        -F "file=@/шлях/до/плану.pdf;type=application/pdf"
   ```
   Назву файлу передавай оригінальну (у ній зазвичай ПІБ пацієнта).
2. Відповідь:
   - `200` — план створено або оновлено. CRM сама знаходить пацієнта за ПІБ / телефоном з PDF.
     Повторне надсилання того ж плану (та сама дата сесії) **не дублює** план — лише оновлює позиції.
   - `422` — PDF не схожий на план OBSERV (текст помилки в `detail`). Не повторюй; напиши адміністратору в бот:
     «План <назва файлу> не прийнято CRM: <detail>».
   - `401/403` — ключ недійсний або без scope write: зупинись і напиши власнику (без самого ключа).
   - `5xx` / мережа — повтори до 3 разів з паузою 1, 5, 30 хв; далі — повідомлення власнику.
3. Після `200` коротко підтвердь лікарю в боті: «✅ План <ПІБ з відповіді: patient.full_name> додано в CRM».
4. **Ті, що вже надіслані, але не потрапили в CRM** — знайди в історії бота PDF-плани за останні 60 днів і передай кожен у CRM тим самим запитом
   (дублікатів не буде). Обовʼязково серед них: Єрошенко Яна, Савицька Надія, Пархоменко Сергій, Голуб Анастасія, Матейчук Ольга, Дзьома Андрій.

## Чого не робити
- Не змінювати й не видаляти плани через інші методи API (PATCH/DELETE) — лише `POST /plans/upload`.
- Не надсилати в CRM фото, переписку пацієнтів чи інші документи — тільки PDF планів.
- Не зберігати PDF планів у своїх логах і не пересилати їх нікуди, крім CRM (медичні дані).
- Не використовувати російські сервіси. Не писати ключ API в чат, файли звітів чи логи.

## Звіт власнику (коротко)
- де саме в коді бота додано передачу (файл / функція);
- скільки старих планів передано: успішно / 422 (з назвами файлів) / помилки;
- результат тестового надсилання одного нового плану.
